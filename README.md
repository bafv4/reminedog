# reminedog

Minecraft Java Edition のサバイバル向けゲーム内ツールです。ゲームの画面にメニューや案内を重ねて表示し、ウェイポイント・高精細のズーム・キーの置き換え・ゲーム内ブラウザを使えるようにします。

## アプリケーション概要

reminedog は Mod ではなく、Java の起動オプション `-agentpath:` で JVM に読み込ませるネイティブのライブラリ（`reminedog.dll`）として動きます。
ゲームのファイルや jar には手を加えず、ゲームのウィンドウの描画と入力に割り込むので、Minecraft のバージョンや Mod ローダーに依存しません。

- 対象：Minecraft Java Edition 1.13 以降（26.x を含みます）。バニラでも、Fabric などの Mod ローダーと一緒でも使えます（1.21.11 に Fabric・Sodium・Iris を入れた構成で確認しています）
- 動作環境：Windows 10 / 11 と 64 ビット（x64）版の Java（Minecraft のランチャーが使う Java は通常これです）。Arm 版 Windows の arm64 版 Java では読み込めません。Linux には対応していません
- ゲーム内ブラウザには Microsoft Edge WebView2 ランタイムが必要です（Windows 11 には最初から入っています）

### 対応状況

| 機能 | 状態 |
|---|---|
| オーバーレイの描画（egui）、メニューと入力の横取り | 実機（1.21.11 と 26.3、NVIDIA）で確認済み |
| 高精細のズーム・キーの変更・設定の保存 | 高精細のズームと倍率の保存は実機（1.21.11 と 26.3）で確認済み。キーの変更は Wine でのみ確認 |
| F3+C によるウェイポイント（記録、一覧、方角と距離） | テスト用のプログラム（GLFW・SDL3）で確認済み、実機では未確認 |
| キーの置き換え（キーとマウスのボタン、ゲーム中だけ） | テスト用のプログラム（GLFW・SDL3）で確認済み、実機では未確認 |
| ゲーム内ブラウザ（WebView2） | WebView2 を動かすテストとテスト用のプログラム（GLFW）で確認済み、実機では未確認 |
| インストーラー（公式ランチャー、Prism Launcher、MultiMC、MCSR Launcher） | 設定ファイルの写しに対して確認済み、本物のランチャーでは未確認 |
| Minecraft 26.x（ウィンドウが GLFW から SDL3 に変わった版） | 対応。26.3 で確認済み |

実機で確かめる手順は [docs/TESTING.md](docs/TESTING.md)、設計と経緯は [docs/HANDOFF.md](docs/HANDOFF.md) にあります。

## 機能

| 機能 | できること |
|---|---|
| メニュー | Ctrl+I でゲームの上にメニューを開き、マウスとキーボードで操作します。キーの割り当て、ズームの倍率、各機能の設定をここで変えられ、設定はインスタンスごとに保存されます |
| ウェイポイント | J で今いる場所を記録し、K で目的地への方角と距離（オーバーワールドとネザーの換算つき）を表示します。目的地を選んでいる間は、画面の左に方角と距離と矢印を表示し続けます。座標は Minecraft の F3+C で取得します |
| 高精細のズーム | Z を押している間、画面の中央を拡大します。ゲームに縦長の解像度で描かせるので、拡大しても細かいところまで見えます |
| キーの置き換え | ゲーム中だけ、Minecraft に届くキーやマウスのボタンを別のキーやボタンに置き換えます（例：マウスのボタン4 → F3、CapsLock → 左 Ctrl） |
| ゲーム内ブラウザ | ゲームの画面の上にウェブページを小さく表示します（ピクチャインピクチャ）。ゲーム中に PageUp／PageDown でスクロールし、矢印キーで動画の再生・一時停止・秒送りができます |
| インストーラー | ランチャーのインスタンスを一覧にし、選んだものに DLL を入れる・外す・最新版に更新する操作ができます |

## インストール方法

[Releases](https://github.com/bafv4/reminedog/releases) の最新の版（`v1.2.0` など）から入れます。名前に `-beta` などが付いた版は試験版です。
リリースの Assets には、版ごとに次のファイルがあります。

- `reminedog-installer-<版>.jar`：インストーラー
- `reminedog-<版>.dll`：本体（PC には `reminedog.dll` という名前で置きます）
- `reminedog-<版>.pdb`：ゲームが落ちたときの調査用（使うときには不要です）

### インストーラーで入れる（おすすめ）

1. `reminedog-installer-<版>.jar` をダウンロードし、ダブルクリックで開きます（Java 8 以降が必要です。開かないときは、コマンドプロンプトで `java -jar reminedog-installer-<版>.jar` を実行します）。画面のタイトルに版が表示されます
2. 入れたいランチャーを閉じておきます
3. 「reminedog の DLL」は「GitHub から最新版をダウンロードする」のまま、保存するフォルダは既定の `C:\reminedog` のままで構いません（空白・日本語を含むフォルダは使えません）
4. 一覧で入れたいインスタンスにチェックを付け、「インストール」を押します。DLL が `C:\reminedog\reminedog.dll` に置かれ、インスタンスの JVM 引数に `-agentpath:C:\reminedog\reminedog.dll` が追加されます
5. ランチャーからゲームを起動し、Ctrl+I でメニューが開けば導入できています

インストーラーの画面でできることの詳細は、下の「インストーラーの詳細」にあります。

### 手で入れる

インストーラーが対応していないランチャーでも、JVM 引数を書ければ使えます。

1. `reminedog-<版>.dll` をダウンロードして `reminedog.dll` に名前を変え、パスに日本語も空白（スペース）も含まないフォルダに置きます（例：`C:\reminedog\reminedog.dll`）。
   JVM 引数は空白で区切られるので、`C:\Program Files` や空白を含むユーザー名のフォルダは使えません（引用符で囲む方法は、ランチャーによっては効きません）。
   ダウンロードした DLL を Windows がブロックしているときは、ファイルのプロパティの「許可する」にチェックを付けます
2. インスタンスの JVM 引数に次を追加します（先頭の `-` を忘れると起動しません）

   ```
   -agentpath:C:\reminedog\reminedog.dll
   ```

   - Prism Launcher：インスタンスの「編集」→「設定」→「Java」→「JVM 引数」
   - 公式ランチャー：「起動構成」→ 構成の「編集」→「その他のオプション」→「JVM 引数」
3. ゲームを起動し、Ctrl+I でメニューが開けば導入できています

### 版を上げる・外す

- **版を上げる**：ゲームを閉じてから、インストーラーでインスタンスにチェックを付けて「最新版に更新」を押します（読み込んでいる DLL を、その場所のまま最新のリリースに置き換えます）。
  手で入れたときは、新しい `reminedog-<版>.dll` を同じ `reminedog.dll` に上書きします。JVM 引数は変えなくて構いません
- **今の版を確かめる**：`reminedog.dll` のプロパティの「詳細」の「ファイル バージョン」、メニューの「状態」の「ビルド」の行、ログの最初の行で確かめられます
- **外す**：インストーラーで「アンインストール」を押します（JVM 引数から外します。DLL のファイルは消しません）。手で入れたときは、JVM 引数から `-agentpath:...` を消します。
  JVM は `-agentpath:` の DLL を読み込めないと起動をやめるので、ゲームが起動しなくなったときもこうして外してください

### インストーラーの詳細

1. **reminedog の DLL**：「GitHub から最新版をダウンロードする」（保存するフォルダの既定は `C:\reminedog`）か、「PC にある DLL を使う」を選びます。
   パスに空白・日本語・`=` が入っていると使えません（理由が赤字で表示されます）。
   ダウンロードでは、GitHub の最新のリリース（試験版を除きます）の DLL を、サイズ・SHA-256・DLL であることを確かめてから `reminedog.dll` として置きます。ダウンロードできるのは、リポジトリが公開されているときだけです（今は非公開です）
2. **インスタンス**：見つけたランチャーのインスタンスが一覧に表示されます。入れたいものにチェックを付けて「インストール」を押します。外すときは「アンインストール」を押します（DLL のファイルは消しません）。
   「状態」の列は、今の JVM 引数に reminedog が入っているか（「導入済み」「未導入」「別の DLL：…」）を表します
3. **最新版に更新**：チェックしたインスタンスが読み込んでいる DLL を、その場所のまま GitHub の最新版に置き換えます（JVM 引数は変えません。上の「reminedog の DLL」の選択は使いません）。
   置き換える DLL と、それを読み込んでいるインスタンスの一覧が表示されるので、確かめてから「はい」を押します。何個のインスタンスが同じ DLL を使っていても、ダウンロードは 1 回だけで、すでに最新版と同じファイルは書き換えません。
   ゲームが読み込んでいる DLL は置き換えられない（そのファイルだけ失敗し、ログに表示されます）ので、ゲームを閉じてから行ってください。`C:\...` のようにドライブから始まらないパスの DLL は置き換えません
4. インストールとアンインストールの前にランチャーを閉じてください。開いたままだと、ランチャーが設定を書き戻して変更が消えることがあります（起動しているランチャーを見つけたら確認が表示されます）

| ランチャー | 探す場所 | 書き換えるもの |
|---|---|---|
| 公式ランチャー | `%APPDATA%\.minecraft` | `launcher_profiles.json`（Microsoft Store 版は `launcher_profiles_microsoft_store.json`）の起動構成の `javaArgs` |
| Prism Launcher | `%APPDATA%\PrismLauncher` | インスタンスの `instance.cfg` の `JvmArgs` と `OverrideJavaArgs` |
| MultiMC | デスクトップ・ダウンロード・ドキュメント・`C:\` の `MultiMC` フォルダ | インスタンスの `instance.cfg` の `JvmArgs` と `OverrideJavaArgs` |
| MCSR Launcher | `%LOCALAPPDATA%\MCSRLauncher` | インスタンスの `instance.json` の `options` |

ほかの場所にあるランチャー（持ち運び用の Prism、別のフォルダの MultiMC など）は「ランチャーのフォルダを追加…」で選びます。

- 引数のほかの部分はそのまま残します。reminedog の引数がすでにあれば、DLL のパスだけを置き換えます（`=log=debug` などのオプションは残します）
- 公式ランチャーで「JVM 引数」を使っていない起動構成には、ランチャーの既定の引数（`-Xmx2G` など）に足して書きます
- Prism・MultiMC で、インスタンスがランチャー全体の JVM 引数を使っているときは、インスタンスの JVM 引数を使うように切り替え、ランチャー全体の引数に足して書きます
- MCSR Launcher で、インスタンスがランチャーの Java の設定を使っているときは、インスタンスの設定に切り替え、ランチャーの Java・メモリー・JVM 引数を写してから足します。
  そのため、後でランチャー側の Java の設定を変えても、そのインスタンスには効かなくなります

### ほかの入手方法

- **GitHub Actions**：リポジトリの Actions タブ → 最新の `CI` の実行 → Artifacts の `reminedog-windows-x64`（DLL）と `reminedog-installer`（インストーラー。版は `dev`）からダウンロードできます
- **自分でビルドする**：下の「開発」を参照してください

## 使用方法

ゲームを起動すると、画面の左上に 10 秒ほど「reminedog：Ctrl+I でメニューを開く」と表示されます。メニューの「状態」の欄には、版（「ビルド」）・ウィンドウのライブラリ・OpenGL の版・ゲームフォルダ・1 フレームの処理時間が表示されます。

### キー

| キー（既定） | 動作 |
|---|---|
| Ctrl+I | メニューを開く／閉じる（開いている間、マウスとキーボードはメニューが受け取ります） |
| Esc | メニューを閉じる |
| Z（ゲーム中に押している間） | 画面の中央を拡大する。倍率はメニューで変えられます |
| J（ゲーム中） | 今いる場所をウェイポイントとして記録する（メニューでは「ウェイポイントを記録」） |
| K（ゲーム中） | 現在地を取り直し、目的地への方角と距離を表示する（メニューでは「現在地を更新」） |
| PageUp／PageDown（ゲーム中、ブラウザを表示しているとき） | ページを 1 画面ぶんスクロールする |
| ↓（同上） | 動画を再生／一時停止する |
| ←／→（同上） | 動画を 10 秒戻す／進める（秒数はメニューで変えられます） |

「ゲーム中」とは、カーソルが消えていて、Minecraft の画面（チャット、インベントリなど）も reminedog のメニューも開いていないときのことです。それ以外のときは、これらのキーはゲームに届きます。
Ctrl+I・Z・J・K は、メニューの「キー」でほかのキーやマウスのボタン（ホイールクリック、ボタン 4・5）に変えられます。ブラウザのキーは、メニューの「ブラウザ」の欄で変えたり外したりできます。
F3 を押している間は、Z・J・K とブラウザのキーをゲームに渡します（F3 との組み合わせはそのまま使えます。Minecraft のキー設定で F3 の代わりのキーを決めていれば、そのキーです。下の「キーの置き換え」で F3 に置き換えたキーやボタンを押している間も同じです）。

メニューの設定は、ゲームフォルダの `reminedog/settings.json` に保存されます（インスタンスごと）。

### ウェイポイント

- J を押すと、今いる場所を「地点 1」「地点 2」…の名前で記録し、画面の上のほうに「「地点 1」を記録した（12, 64, -7）」と表示します。
  ワールドごと（シングルプレイはワールドのフォルダ、マルチプレイはサーバーごと）に、ゲームフォルダの `reminedog/waypoints/` に保存します
- メニューの「ウェイポイント」の欄に、今のワールド、最後に取得した現在地、記録した地点の一覧が表示されます。名前を押すと、その地点が目的地になります。「名前を変える」と「削除」もここで行います。
  「現在地を記録」と「現在地を更新」のボタンは、メニューを開いたままでも使えます
- K を押すと現在地を取り直し、目的地への方角と距離を 8 秒間表示します（例：`地点 3：北東 128 m（右に 35°・12 m 上）`。左右は今向いている方向から見たものです）。
  オーバーワールドとネザーの間は、座標を換算して表示します。目的地を選んでいなければ、座標は取得せずにそのことを知らせます
- 目的地を選んでいる間は（メニューを閉じているとき）、画面の左に目的地の名前・座標と、最後に取得した現在地からの方角と距離を表示し続けます。
  方角は矢印でも示します（通知とメニューの一覧にも表示されます）。矢印は、座標を取得したときに向いていた方向を上とします。reminedog が向きを知るのは F3+C のときだけなので、矢印と距離が変わるのは J・K・自分の F3+C を押したときだけです
- 自分で F3+C を押したときも、現在地を更新します（クリップボードにはいつもどおり座標が入ります）

座標は Minecraft の F3+C で取得します（下の「仕組みの説明」）。そのため、次の制限があります。

- 記録や更新のたびに、チャットに「［デバッグ］：クリップボードに座標をコピーしました」と表示されます（Minecraft が出すものなので消せません）。実際にはクリップボードは変わりません
- デバッグ情報が制限されたワールドやサーバー（ゲームルール `reduced_debug_info` など）では、座標を取得できません。そのとき、C に割り当てたほかの操作（「アイテムを捨てる」など）が 1 回動くことがあります。
  一度断られたワールドでは、メニューの「もう一度試す」を押すまで F3+C を送りません
- F3・C（Minecraft のキー設定の、デバッグの修飾キー・座標のコピー・クラッシュのキー）を押している間は、座標を取得できません。C に「アイテムを捨てる」も割り当てているときは、Ctrl を押している間も取得できません（断られたときにスタックごと捨てないためです）
- 記録キーと更新キーには、Ctrl との組み合わせを割り当てられません
- F3 と C の割り当ては、ゲームフォルダの `options.txt` から読みます（キー設定で変えていても使えます。ただし、マウスのボタンなど対応していないキーがあります）
- ワールドは `logs/latest.log` と `saves` のフォルダから判定します。SeedQueue のように裏でワールドを作る Mod を入れていると、判定できません
- シングルプレイはワールドのフォルダ名で区別します。ワールドを消して同じ名前で作り直すと、前のワールドの地点がそのまま表示されます（`reminedog/waypoints/sp-<名前>.json` を消すと空になります）

### ズーム

既定では「高精細」で拡大します。ズームキーを押している間だけ、ゲームに縦に倍率ぶん長い解像度（例：2560×1440 で 4 倍なら 2560×5760）で描かせ、その中央を画面に表示します。
Minecraft の視野角は縦方向で決まるので、縦に長く描かせると同じ視野に多くの画素が入り、拡大しても細かいところまで見えます（スピードランの「縦長の解像度」と同じ考え方です）。

- 描く画素が倍率ぶん増えるので、そのぶん重くなります。倍率の上限は GPU が扱える大きさ（多くは 16384 px）で決まります
- 押した瞬間と離した瞬間に、ゲームが画面の大きさの変更を処理します（一瞬引っかかることがあります）
- 拡大している間は、画面の下の HUD（ホットバーなど）は見えません。クロスヘアは見えます
- 高精細が使えないとき（OpenGL 3.0 未満など）や、メニューで「高精細にする」を外したときは、描かれた画面の中央を引き伸ばします

### キーの置き換え

ゲーム中だけ、Minecraft に届くキーやマウスのボタンを、別のキーやマウスのボタンに置き換えます。例：マウスのボタン4 → F3（横のボタンで F3 の組み合わせを使う）、CapsLock → 左 Ctrl、マウスのボタン5 → C。
キーとマウスのボタンのどの組み合わせでも構いません。元のキーはゲームに届かず、置き換え先だけが届きます。
Minecraft のキー設定で変えられる操作（前進、アイテムを捨てる など）は、キー設定で変えるほうが適しています。置き換えは、キー設定では変えられないキー（Ctrl+Q でまとめて捨てるときの Ctrl、古い版の F3 など）に使ってください。

- メニューの「キーの置き換え（N 個）」の欄（「ウェイポイント」の下にあり、押すと開きます）で設定します
  - 「追加」を押し、置き換えるキーかマウスのボタンを押してから、ゲームに送るキーかマウスのボタンを押します。どちらを待っている間も、Esc か「取り消し」で取り消せます。
    ここで押したキーやボタンは、離したときもゲームに届きません（F3 を押して置き換え先にしても、メニューの裏で F3 画面は切り替わりません。メニューの「キー」でキーを割り当てるときも同じです）
  - 左クリック・右クリック・ホイールクリックに置き換えるときは、置き換え先を待っている間に表示される同じ名前のボタンを押します（左右のクリックはメニューの操作に使うので、押しても取得できません）。置き換えるキーにできるマウスのボタンは、ホイールクリックとボタン 4・5 です
  - 各行には、置き換え先に Minecraft のキー設定で割り当てている操作を添えます（options.txt から読みます）。例：`マウスのボタン4 → F3（オーバーレイの切り替え・デバッグ修飾キー）`
  - 「削除」を押すと、確認なしでその行を消します。「キーの置き換えを使う」を外すと、すべての置き換えが止まります
  - 置き換えは 32 個まで作れます
- 置き換えるキーにできないもの：Esc、Windows キー、PrintScreen、日本語配列などの言語のキー（ろ・¥・変換・無変換・カタカナ/ひらがな など。離したイベントが来ないことがあるためです）、修飾キーなしの reminedog のキー（既定では Z・J・K と、ブラウザの PageUp・PageDown・↓・←・→。ブラウザのキーはメニューの「ブラウザ」の欄で外せます）、もう置き換えているキー。
  ゲームに送るキーにできないもの：Esc、Windows キー
- reminedog のキー（Ctrl+I・Z・J・K）は、置き換える前の物理的なキーで判定します（左 Ctrl → F3 にしても、Ctrl+I でメニューが開きます）。元のキーを reminedog のキーやその修飾キーにも使っていると、行の下に警告が表示されます。置き換えの元のキーは、メニューの「キー」で reminedog のキーに割り当てられません。
  「キーを元に戻す」でも、既定のキーが置き換えの元のキーになっている操作は今のキーのまま残し、「Z は置き換えに使っている」のように表示します（残したキーと重なる、ほかの操作の既定のキーも戻しません）
- 置き換えは、ゲームフォルダの `reminedog/settings.json` に保存されます（インスタンスごと）

```json
  "rebinds_enabled": true,
  "rebinds": [
    { "from": "key.mouse.4", "to": "key.keyboard.f3" },
    { "from": "key.keyboard.caps.lock", "to": "key.keyboard.left.control" }
  ]
```

キーの名前は Minecraft 26.x の options.txt と同じです（`key.keyboard.f3`、`key.keyboard.left.control`、`key.mouse.left`、`key.mouse.4` など）。1.21 以前のインスタンスでも 26.x の名前で書きます。
1.21 と 26.x で名前が違うキーがあります：テンキーの「.」は `key.keyboard.keypad.period`（1.21 では `keypad.decimal`）、アプリケーションキーは `key.keyboard.application`（1.21 では `menu`）、ISO 配列の追加のキーは `key.keyboard.world.1`（1.21 では `world.2`）です。26.x の `keypad.decimal`・`menu`・`world.2` は別のキーを指します。
名前のないキーは、SDL3 のスキャンコードで `key.keyboard.<番号>` と書けます。
メニューで押せないキー（F13 以降のキーや、US 配列のキーボードにない日本語配列のキー）への置き換えや、左右のクリックを元にする置き換えは、ゲームを終了してから settings.json に書けば使えます（起動中は読み直さず、メニューで設定を変えると上書きされます）。
読めない名前や使えない組み合わせは使わず、メニューの行の下に理由が表示されます。この版のゲームが扱えないキー（1.21 以前のインスタンスでの、GLFW にない SDL3 だけのキー。1.21 の名前のまま書いた `key.keyboard.menu` もこれに当たります）は、「キー 118 はこの版のゲームでは使えない」のように表示されます。
`"rebinds_enabled"` は `true` か `false` です（`"true"`・`"false"` の文字列でも構いません）。`from` か `to` がない項目のように形の違う項目や値は読み飛ばし、元のファイルを `reminedog/settings.rebinds-<数字>.json` に写して残します（数字は時刻です）。
メニューの「キーの置き換え」の欄には「settings.json の置き換えに読めない項目があったので settings.rebinds-<数字>.json に残した」と表示されます。
読み飛ばした項目は、次にメニューで設定を変えたときに settings.json から消えます（それまでは、起動しても同じ写しを使い、写しは増えません）。

制限：

- 置き換えるのは、ゲーム中に押したときだけです。チャット、インベントリなどの画面と、reminedog のメニューを開いている間は元のキーのままです（チャットには元のキーの文字が入ります）
- 置き換えたキーを押したまま画面やメニューを開いても、離すまでは置き換え先を押したままにします（画面の中で離せば、置き換え先も離します）。置き換え先のリピートは、ゲーム中だけ送ります
- 置き換えで開いた画面は、置き換え先のキーか Esc で閉じます。画面の中では置き換えないので、元のキーでは閉じません（マウスのボタン5 → E で開いたインベントリは、マウスのボタン5 では閉じません）
- マウスのボタンをキーに置き換えると、押し続けてもリピートしません（マウスのボタン5 → Q を押し続けても 1 個しか捨てません）。キーをマウスのボタンに置き換えると、キーのリピートは送りません（押し続けている間は、ボタンを押したままです）
- 1.21.9 以降（1.21.11、26.x）では、画面の中のクリックの修飾キーは、実際に押しているキーで決まります（Shift に置き換えたキーを押しながらインベントリのアイテムをクリックしても、Shift+クリックになりません）。
  1.21.8 以前（確かめたのは 1.16.1）は、ゲームが Shift の状態を読むので、置き換えた Shift でも Shift+クリックになります。
  どの版でも、Ctrl を押しながらのブロック選択のように、キーの状態を読む操作は置き換えに従います
- Windows キー、Alt+Tab、CapsLock や NumLock のロック（ランプ）は Windows が先に処理するので、置き換えても止まりません（CapsLock → 左 Ctrl でも、押すたびに大文字の入力が切り替わります）
- IME がオンのときは、キーが IME に取られてゲームに届かないことがあります（1.21 以前の GLFW は、IME が処理したキーを捨てます）。
  元のキーを離したイベントが届かなくても、Windows がそのキーやボタンを離していると報告していれば、0.1 秒ほどで置き換え先を離します。その後で遅れて離したイベントが届くと、元のキーのままゲームに届きます
- 26.x は、ワールドに入るとき（「選択したワールドで遊ぶ」など）や「セーブしてタイトルへ戻る」の間、届いた入力のイベントを捨てます。
  そのとき離したキーやボタンが置き換え先と同じだと（ワールドに入るときの左クリックと H → 左クリック など）、Windows が離していると報告してから 0.1 秒ほどで、離したとみなします（ゲームには何も送りません。ゲームは画面が変わったときに自分で離しています）
- F3 に置き換えたキーを押したまま C を 10 秒押し続けると、F3+C を押し続けたときと同じく、Minecraft のデバッグ用のクラッシュでゲームが落ちます
- 置き換えで F3・C（座標を取得するためのキー）を押している間は、座標を取得できません（「マウスのボタン4（F3 に置き換え）を押している間は座標を取得できない」のように表示されます）。C に「アイテムを捨てる」も割り当てているときは、置き換えで Ctrl を押している間も取得できません
- 日本語配列（JIS）のキーボードでは確かめていません。記号のキーは US 配列の記号で表示します
- `overlay=off` のときや、オーバーレイが動いていないとき（初期化に失敗したときなど）は、置き換えも効きません
- キーボードのキーを置き換えるには、ゲームがキーの状態を読む関数（`glfwGetKey`、`SDL_GetKeyboardState`）のフックが必要です。フックできなかったときは、マウスのボタンを元にする置き換えだけを使い、メニューにその理由が表示されます

### ブラウザ

ゲームの画面の上に、ウェブページを小さく表示します（ピクチャインピクチャ）。攻略の記事を読んだり、動画を見たりしながら遊べます。
Windows に入っている Microsoft Edge WebView2 ランタイムを使います（ない場合はメニューに「WebView2 ランタイムが見つかりません」と表示されます）。

- メニューの「ブラウザ」の欄（押すと開きます）の「表示する」で表示します。最初に表示したときに起動し、最後に開いていたページ（初めては Google）を開きます。
  同じ欄のキーの表で「ブラウザの表示／非表示」にキーを割り当てれば、ゲーム中にそのキーで開閉できます（既定は割り当てなしです）
- 表示する場所は、はじめは画面の右上です。**メニューを開いている間だけ**、ブラウザの窓のタイトルをドラッグして動かし、ページの右下の角をドラッグして大きさを変えられます。位置と大きさは保存され、メニューを閉じてもそのままです
- メニューを開いている間は、ページをクリック・ホイール・ドラッグで操作でき、クリックしたページの入力欄に文字を打てます（日本語は確定した文字だけです。変換中の文字は表示されません）。
  上の欄は ⏴（戻る）・⏵（進む）・⟳（再読み込み）とアドレス欄です。アドレス欄に URL か言葉を入れて Enter を押すと開きます（言葉なら Google で検索します）
- メニューを閉じている間は、ページを表示するだけで、マウスとキーボードはゲームが受け取ります。ゲーム中は次のキーが使えます（チャットやインベントリなどの画面を開いているときや、F3 を押している間はゲームに渡します）
  - PageUp／PageDown：ページの中央にあるものを 1 画面ぶんスクロールします
  - ↓：動画を再生／一時停止します。←／→：10 秒戻す／進めます。操作した動画の位置が画面の上のほうに表示されます（例：`一時停止　1:23 / 10:00`）。
    対象は、再生中の動画（または音声）で、なければページに表示されている一番大きいものです
- 「非表示にする」（または窓の ×）で隠すと、再生中の動画を一時停止し、表示し直すと続きから再生します。
  記事に埋め込まれた動画（iframe の中の YouTube など）は止められないので、隠している間はブラウザの音を消します（埋め込みの動画は再生が続きます）
- 「終了」でブラウザを止めます（メモリーを空けます。次に表示すると起動し直します）
- 「ページの拡大率」でページの文字や画像の大きさを、「不透明度」でメニューを閉じているときの透け具合を変えられます
- ログイン（YouTube など）やクッキーは `%LOCALAPPDATA%\reminedog\WebView2` に保存され、すべてのインスタンスで共有します
- ゲームの前に別のウィンドウを出さないように、右クリックメニュー・印刷・ダウンロード（「ブラウザではダウンロードできません」と表示されます）・ファイルの選択（アップロード）・ほかのアプリを開くリンク（`mailto:` など）・カメラなどの許可の要求は使えません。
  新しいウィンドウで開くリンクは、同じ画面で開きます。`alert` は自動で閉じ、確認のダイアログは「キャンセル」になります
- できないこと：タブ、ブックマーク、記事に埋め込まれた動画のキー操作（クリックでは操作できます）、`<select>` の候補などページの外に出る部品（表示されないことがあります）、DRM のある動画（黒くなります）、Esc キー（メニューを閉じるのに使います）

### オプション

`-agentpath:C:\reminedog\reminedog.dll=log=debug,scale=1.5` のように、`=` の後ろにカンマ区切りで書きます。

| キー | 値 | 既定 |
|---|---|---|
| `gamedir` | ゲームフォルダのパス（自動判定が外れるとき） | `--gameDir` の引数、なければ作業フォルダ |
| `log` | `off` / `error` / `warn` / `info` / `debug` / `trace` | `info` |
| `overlay` | `on` / `off`（`off` ならフックだけ入れて何も描きません） | `on` |
| `scale` | UI の拡大率（0.5〜4） | `1` |

### ログとうまく動かないとき

- ログはゲームフォルダの `reminedog/reminedog.log` に出力されます（Prism Launcher ならインスタンスの `minecraft` フォルダ、公式ランチャーなら起動構成の「ゲームディレクトリ」で、空欄なら `%APPDATA%\.minecraft` です）。
  実際のフォルダは、メニューの「状態」の「ゲームフォルダ」の行とログの `game dir:` の行に表示されます。詳しいログが必要なときは `=log=debug` を付けます
- ログには、Minecraft の起動引数（ログインのトークンが入っています）とブラウザのページの URL（クエリにトークンが入ることがあります）を書きません。ページはホスト名だけを出力します
- ゲームが起動しなくなったときは、JVM 引数から `-agentpath:...` を外してください（インストーラーの「アンインストール」でも外せます）。JVM は `-agentpath:` の DLL を読み込めないと起動をやめます

## 仕組みの説明

詳しい設計と、採らなかった案・確かめたことは [docs/HANDOFF.md](docs/HANDOFF.md) にあります。

### 読み込み

- `reminedog.dll` は JVM のエージェント（JVMTI の `Agent_OnLoad` を持つ DLL）として、ゲームのコードより先に読み込まれます。そこでオプションとログを準備し、DLL の読み込みの監視（`LdrRegisterDllNotification`）を始めます
- ゲームが LWJGL のウィンドウのライブラリ（1.21 までは GLFW、26.x は SDL3）と `opengl32.dll` を読み込んだら、必要な関数に MinHook でフック（デトア）を入れます。フックの中で問題が起きても、ゲームは止めません（失敗したら何もしません）

### オーバーレイの描画

- 画面を表示する関数（GLFW の `glfwSwapBuffers`、SDL3 の `SDL_GL_SwapWindow`）が呼ばれるたびに、自前の OpenGL コンテキストに切り替えて、egui（Rust の UI ライブラリ）でメニューや案内を描き、ゲームのコンテキストに戻します。ゲームの OpenGL の状態には触れません
- 日本語は Windows のフォント（游ゴシック → メイリオ → MS ゴシック）で描きます

### 入力

- GLFW ではゲームのキー・マウス・文字のコールバックを差し替え、SDL3 では `SDL_PollEvent` で受け取るイベントを選り分けて、入力をひとつずつ「ゲームに渡す／横取りする／置き換える」に振り分けます
- メニューを開いている間は、キーとマウスをメニュー（egui）に渡し、離したイベントだけゲームにも渡します（ゲームの中でキーが押されたままにならないようにするためです）。
  ゲーム中にメニューを開いたときは、ゲームがカーソルを隠して捕まえているので、カーソルを自前で描き、Windows のポインターの速度の設定に合わせて動かします

### ウェイポイント（F3+C）

- 記録・更新のときに、reminedog がゲームに F3+C のキーを送ります（GLFW ではゲームのキーのコールバックを直接呼び、SDL3 ではキーのイベントを差し込みます）。Minecraft がクリップボードに書こうとした座標と向きを横取りして読み、OS のクリップボードには渡しません
- どのキーを送るかは、ゲームフォルダの `options.txt`（キー設定）から読みます。今いるワールドは `logs/latest.log` と `saves` のフォルダから判定します

### 高精細のズーム

- ズームキーを押している間、ゲームにはウィンドウが縦に倍率ぶん長いと伝えます（ウィンドウの大きさを問い合わせる関数の答えと、大きさの変更の知らせを変えます）
- ゲームが画面（フレームバッファ 0）に描こうとしたら、reminedog の縦長のフレームバッファに描かせ（`wglGetProcAddress` のフックで、ゲームに渡す `glBindFramebuffer` などを差し替えます）、表示のときにその中央をウィンドウに写します
- ゲームが縦長で描いていないと分かったときは、描かれた画面の中央を引き伸ばす方式に切り替えます

### キーの置き換え

- 置き換えるかどうかはキーやボタンを押したときに決め、そのリピートと離したときは、押したときの決定に従います（途中でルールや画面が変わっても、ゲームの中にキーが押されたまま残らないようにするためです）
- GLFW では置き換え先をゲームのコールバックに送り、SDL3 ではイベントをその場で書き換えます。ゲームがキーの状態を直接読む関数（`glfwGetKey`、`SDL_GetKeyboardState`）の答えも、「元のキーは離していて、置き換え先は押している」状態に合わせます
- 離したイベントが届かないとき（IME に取られたときなど）は、Windows のキーの状態を見て置き換え先を離します

### ゲーム内ブラウザ

- 最初に表示したときに、専用のスレッドで Microsoft Edge WebView2 を「画面に出さない」形（visual hosting）で作ります。ページの絵は Windows の画面の取り込み（Windows.Graphics.Capture）で受け取ってメモリーに写し、ゲームのスレッドが毎フレーム新しい絵を OpenGL のテクスチャに上げてオーバーレイに描きます
- ページへのクリックやキーは、ウィンドウのメッセージではなく Chrome DevTools Protocol（CDP）で送ります。これで Windows のフォーカスがゲームから移りません（全画面のゲームが最小化されません）
- 動画の操作は、ページに小さなスクリプトを流して行います。右クリックメニュー・ダイアログ・新しいウィンドウ・ダウンロードなど、ゲームの前にウィンドウを出すものは止めるか、同じ画面で開きます

### インストーラー

- Kotlin で書いた 1 つの jar で、Java 8 以降で動きます。ランチャーの設定ファイルを読み、JVM 引数の reminedog の部分（とそれを効かせるための設定）だけを書き換えます。ほかの行・キー・引数は文字のまま残し、書き込みは一時ファイルからの置き換えで行います
- DLL のダウンロードでは、GitHub の API で最新のリリースを探し、サイズ・SHA-256・DLL の形式を確かめてから置き換えます

## 開発

### 構成

```
core/      OS に依存しない処理（テストあり）：F3+C のパース、options.txt のキー設定とキーの名前の表、ウェイポイントの保存、ワールドの判定、方角と距離、
           設定、ブラウザへの入力（CDP）・アドレス欄・動画のスクリプト、ログ
render/    glow + egui_glow によるオーバーレイの描画（OS に依存しない、テストあり）：メニュー、入力の振り分け、キーの置き換えの状態、ズームの計算、ブラウザの窓
hook-win/  Windows 用のエージェント（reminedog.dll）：DLL の読み込みの監視、デトア、GLFW・SDL3 のフック、WGL、高精細のズーム、ブラウザ（WebView2）
installer/ インストーラー（Kotlin、Swing＋FlatLaf、Gradle）：DLL を置き、ランチャーのインスタンスの JVM 引数に -agentpath を足す
ci/        DLL の確認のスクリプト（check-dll.ps1）と、LWJGL で Minecraft と同じようにウィンドウを作るテスト用のプログラム（ci/smoke/。GLFW 版と SDL3 版）
scripts/   Linux 上で Wine を使ってエージェントを動かすスクリプト
```

ファイルごとの役割は [CLAUDE.md](CLAUDE.md) の「構成」にあります。

### ビルドとテスト（Windows）

[Rust](https://rustup.rs/)（1.95 以降）と Visual Studio Build Tools（C++ によるデスクトップ開発）を入れて、次を実行します。

```
cargo build --release -p reminedog-hook-win      # target\release\reminedog.dll
cargo test --workspace
cargo clippy --workspace --all-targets
```

- MSVC では CRT を静的にリンクします（`.cargo/config.toml` の `+crt-static`。Java 8 に vcruntime140 がないためです）
- ブラウザ（WebView2）を実際に動かすテストは、WebView2 ランタイムと画面のあるセッションが必要なので、通常は実行しません：`cargo test -p reminedog-hook-win browser -- --ignored --test-threads=1`
- コミットする前に `cargo fmt --all`、clippy（警告 0）、テストを通してください

### Linux から（Wine）

```sh
cargo test --workspace                 # core と render のテスト（Linux でも動く）
cargo clippy --workspace --all-targets
rustup target add x86_64-pc-windows-gnu                           # 初回のみ。mingw-w64 も必要
cargo build -p reminedog-hook-win --target x86_64-pc-windows-gnu   # Linux から Windows 向けにビルド
scripts/wine-smoke.sh --agent target/x86_64-pc-windows-gnu/debug/reminedog.dll --screenshot shot.png
```

GNU でビルドした DLL には、ゲーム内ブラウザは入りません（WebView2 などの DLL を Wine で読み込めるか分からないためです）。

`scripts/wine-smoke.sh` は、Wine 上の Windows 版 Java で LWJGL のウィンドウを開き、エージェントを読み込ませて動作を確かめます。
必要なもの：64 ビットの Wine、Xvfb（`xvfb-run`、Mesa の GLX）、JDK 9 以降の `javac`、pip の入った `python3`、`curl`、`flock` と `timeout`。
初回は PyPI（Windows 版 Java）と Maven Central（LWJGL）からダウンロードし、`target/wine-cache` に Wine の環境を作ります（`cargo clean` で消えます）。
`--screenshot` を付けると、最後のフレームを PNG で保存します。
`--seconds 8 --capture --xdotool "key ctrl+i"` のように、秒数を決めて動かし、`xdotool` でキーやマウスの操作を送れます（`--sdl` で SDL3 版になります）。
`--mc` を付けると、Minecraft と同じように自前のフレームバッファに描いてからウィンドウに転送するので、高精細のズームを試せます（例：`--capture --mc --xdotool "keydown z sleep 2" --grab zoom.png` で Z を押したままの画面を保存します）。
日本語を表示するには、日本語フォントを `target/wine-cache/prefix/drive_c/windows/Fonts/msgothic.ttc` などの名前で置きます（`~/.wine` ではありません。初回の実行でフォルダができます）。

### インストーラー

Gradle でビルドします（JDK 17 以降が必要です。Gradle は初回に `gradlew` がダウンロードします）。

```
cd installer
gradlew build      # テストと installer\build\libs\reminedog-installer.jar（Linux は ./gradlew build）
```

jar には FlatLaf と Kotlin のライブラリが入っていて、Java 8 以降で動きます。

### CI

GitHub Actions（`.github/workflows/ci.yml`）で、push のたびに次を行います。

- Linux：fmt、clippy、テスト、mingw でのクロスビルドの clippy
- インストーラー：テストと jar のビルド（成果物 `reminedog-installer`）
- Windows：clippy、テスト、リリースビルド、`ci/check-dll.ps1` での DLL の確認（`Agent_OnLoad` があること、CRT を静的にリンクしていること）、成果物 `reminedog-windows-x64`
- Windows のスモークテスト：テスト用のプログラムに DLL を読み込ませます（LWJGL 3.2.2／Java 8、3.3.3／Java 21、3.4.3／Java 25 の SDL3。Mesa の llvmpipe で描きます）

### リリース

GitHub の Actions タブ → `Release` → 「Run workflow」で、版（`1.2.0`、試験版なら `1.2.0-beta.1`）を入れて実行します。

- 実行したブランチの最新のコミットで、clippy とテストを通してから DLL とインストーラーをビルドし、下書き（Draft）のリリース `v<版>` を作ります。版の名前は、DLL とインストーラーのファイル名と中身（DLL のバージョン情報とログ、インストーラーの manifest とタイトル）に入ります。リポジトリの `Cargo.toml` の版は変えません
- 同じ版のタグかリリース（下書きを含みます）がすでにあれば止まります
- 下書きを確かめてから、GitHub の画面で公開します。公開したときにタグが作られます。`-` を含む版は試験版（pre-release）になり、インストーラーの「最新版」には使われません
