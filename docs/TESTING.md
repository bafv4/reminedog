# 確認手順

- プロトタイプ 1（オーバーレイの表示）：1.21.11 と 26.3 で確認済み
- プロトタイプ 2（メニューの操作）：1.21.11 と 26.x で確認済み
- 高精細のズーム・キーの変更・設定の保存：下の「ズームとキーの変更で確認すること」
- プロトタイプ 3（F3+C によるウェイポイント）：下の「ウェイポイントで確認すること」

## 準備

1. `reminedog.dll` を入手する（[README](../README.md#dll-の入手)）
2. パスに日本語も空白（スペース）も含まない場所に置く（例：`C:\reminedog\reminedog.dll`。`C:\Program Files` は不可）
3. 確かめたいインスタンスの JVM 引数に `-agentpath:C:\reminedog\reminedog.dll` を追加する

## ウェイポイントで確認すること

1.21.11 と 26.3 の両方で確かめてほしい。1.16.1 は対象外（手元の 1.16.1 はスピードラン用の Mod を入れた構成で、ワールドを判定できない）。

J と K は、Minecraft の F3+C で座標を取る。reminedog が送った F3+C でも、チャットに「［デバッグ］：クリップボードに座標をコピーしました」（英語のゲームでは "[Debug]: Copied location to clipboard"）と出るが、クリップボードは書き換えない。

### 準備

1. ゲームを起動し、メニュー（Ctrl+I）の「キーを元に戻す」を押す（メニューを開く Ctrl+I、ズーム Z、ウェイポイントを記録 J、現在地を更新 K になる）
2. メモ帳などで、何か文字をコピーしておく（クリップボードが書き換わらないかを見るため）
3. 確かめるワールドに入り、「LAN に公開」でチートを許可する（英語のゲームでは "Open to LAN" → "Allow Commands"）（下で `/execute` と `/gamerule` を使う。今のワールドはコマンドを使えない設定になっている）。`/gamemode creative` にしておくと、テレポートの先で落ちたり埋まったりしても死なない
4. C に「アイテムを捨てる」を割り当てているインスタンス（26.3 など）では、手に何も持たないでおく（拒否の確認で、1 回捨てることがある）
5. サーバーでの確認は、できればでよい

### 記録

- [ ] ゲーム中に J を押すと、画面の上のほう（クロスヘアより上）に「「地点 1」を記録した（12, 64, -7）」のように出る（数字は今いる場所）
- [ ] チャットに「［デバッグ］：クリップボードに座標をコピーしました」と出るが、メモ帳に貼り付けると、準備の 2 でコピーした文字のまま
- [ ] F3 画面が開いていない。続けて A で左に歩いても、チャットに［デバッグ］の行（チャンクの再読み込みなど）が出ない（F3 が押されたままになっていない）
- [ ] J を押すたびに「地点 2」「地点 3」と増える
- [ ] Ctrl を押しながら J を押す。C に「アイテムを捨てる」を割り当てているインスタンス（26.3）では「F3・C か Ctrl を押している間は座標を取得できない」と出て、何も捨てない。それ以外（1.21.11。Ctrl がダッシュ）では、Ctrl を押したまま（走りながら）でもふつうに記録できる
- [ ] 記録キーに Ctrl+L などを割り当てようとすると、「Ctrl との組み合わせ（Ctrl+L）は「ウェイポイントを記録」に使えない」と出る

### メニュー

- [ ] Ctrl+I でメニューを開くと、「ウェイポイント」の欄に「ワールド：<ワールドのフォルダ名>」、「現在地：12, 64, -7（オーバーワールド・15 秒前）」のような行、記録した地点の一覧が出る
- [ ] C に「アイテムを捨てる」を割り当てているインスタンス（26.3）では、「C には「アイテムを捨てる」も割り当てられている。座標を取得できないワールドでは、その操作が 1 回動くことがある」と警告が出る。1.21.11 の既定（C に「ホットバーの保存」）では出ない（押している間の状態しか見ない操作なので、動かない）
- [ ] メニューを開いたまま「現在地を記録」と「現在地を更新」を押せる。記録の通知がメニューに隠れずに出る。「現在地」の「N 秒前」が 0 に戻る
- [ ] インベントリを開いた状態でメニューを開くと、この 2 つのボタンは押せず、「ゲームの画面を閉じると使える」と出る
- [ ] タイトル画面に戻ってメニューを開くと「ワールドに入っていない」と出る

### 目的地と方角

- [ ] 一覧の名前を押すと、選ばれた表示になる（もう一度押すと外れる）
- [ ] 目的地を選ばずに K を押すと、「目的地が選ばれていない（メニューで選ぶ）」と出て、チャットに［デバッグ］の行が出ない
- [ ] 目的地を選び、しばらく歩いてから K を押すと、「地点 1：北東 128 m（右に 35°・12 m 上）」のような通知が 8 秒ほど出る。方角・距離・左右・高さの差が実際と合う（北は Z が減る向きで、F3 画面の `Facing: north`。高さの差が 3 m 未満なら出ない）
- [ ] メニューの一覧の方角と距離は、最後に座標を取ったとき（J か K を押したとき）の位置からのもの
- [ ] Z を押したまま J や K を押しても、通知が拡大の表示に隠れない

### 画面左の目的地と矢印

- [ ] 目的地を選んでメニューを閉じると、画面の左の中ほどに「目的地：地点 1」、ディメンションと座標、方角と距離（「北東 128 m・12 m 上」など）、「15 秒前の位置と向きから」が出続ける。目的地を外すと消える。メニューを開いている間は出ない
- [ ] 座標をまだ取っていないワールドでは「現在地が未取得（K で更新）」と出る
- [ ] 左の表示の大きな矢印が、K を押したときに向いていた方向を上として、目的地の方を指す（真後ろなら下、右に 90° なら右）。視点を回しても矢印は変わらず、もう一度 K（か J、自分の F3+C）を押すと向きが直る
- [ ] K の通知と、メニューの一覧の各行にも小さな矢印が出て、左の表示の矢印と同じ向きを指す。目的地のすぐそば（「ここ」）や別のディメンションでは矢印が出ない
- [ ] 左の表示が、チャットやホットバー、F3 画面を開いたときの文字と重なって読めなくならないか（重なるなら知らせてほしい）

### 名前の変更と削除

- [ ] 「名前を変える」を押すと入力欄が出て、日本語（IME）で入力できる（変換中の文字は欄に出ない。確定すると入る）
- [ ] IME の変換を確定する Enter で、名前の変更まで決まってしまわない（決まってしまうなら知らせてほしい）。もう一度 Enter を押すか「決定」で名前が変わる。「取り消し」で元の名前に戻る。欄を空にすると「決定」を押せない
- [ ] 名前の入力中に Esc でメニューを閉じると、変更は取り消される（開き直すと元の名前）
- [ ] 「削除」を押すと「もう一度押すと削除」に変わり、もう一度押すと消える。1 回だけ押してメニューを閉じ、開き直すと「削除」に戻っている

### ディメンション

- [ ] オーバーワールドの地点を目的地にして、`/execute in minecraft:the_nether run tp @s ~ ~ ~` でネザーに移り、K を押すと「地点 1（ネザーでは 16, -1）：北 20 m（正面）」のように、ネザーの座標に換算して出る
- [ ] `/execute in minecraft:the_end run tp @s 0 100 0` でジ・エンドに移って J で記録する。`/execute in minecraft:overworld run tp @s ~ ~ ~` で戻り、その地点を目的地にして K を押すと、「地点 N は別のディメンション（ジ・エンド）」と出る。メニューの一覧でも「別のディメンション」と出る

### 自分で押す F3+C と、F3 との組み合わせ

- [ ] 自分で F3+C を押すと、クリップボードに座標が入り（メモ帳に貼ると `/execute in minecraft:overworld run tp @s …`）、メニューの「現在地」が更新される。目的地を選んでいれば、方角と距離の通知も出る
- [ ] F3 を押したまま J・K・Z を押しても、reminedog は反応しない（ゲームに渡る）
- [ ] チャットに J や K を入力できる。インベントリを開いた状態で J や K を押しても、何も記録されない

### 座標を取れないワールド（手に何も持たずに）

- [ ] `/gamerule reduced_debug_info true` にしてから J を押すと、「座標を取得できなかった（このワールドではデバッグ情報が制限されている）」と出る。C にほかの操作を割り当てていれば「。C の操作（アイテムを捨てる）が 1 回動いた可能性がある」と続く。F3 画面は開いたままにならない
- [ ] 続けて J を押すと、「このワールドでは座標を取得できない（メニューの「もう一度試す」で再開）」と出て、何も起きない（アイテムも捨てない）。目的地を選んで K を押しても同じ。メニューに「このワールドでは座標を取得できない（デバッグ情報が制限されている）」と「もう一度試す」が出る
- [ ] `/gamerule reduced_debug_info false` に戻し、メニューの「もう一度試す」を押すと、J でまた記録できる

### ワールドの切り替えと再起動

- [ ] 新しいワールドを作って入ると、メニューのワールドの名前が変わり、一覧が空になる。元のワールドに戻ると、記録した地点が残っている
- [ ] ゲームを再起動しても地点が残っている（ゲームフォルダの `reminedog/waypoints/sp-<ワールドのフォルダ名>.json`）

### キーの変更

- [ ] メニューの「キー」で「ウェイポイントを記録」の行のボタン（J）を押してから Z を押すと、「Z は「ズーム」と重なるので使えない」と出て、変わらない
- [ ] 同じように C を押すと、「C は F3+C に使うキーなので使えない」と出る
- [ ] マウスのボタン 4 や 5 を「ウェイポイントを記録」や「現在地を更新」に割り当てられ、そのボタンで動く
- [ ] 「キーを元に戻す」で J と K に戻る

### ログ

- [ ] ゲームフォルダの `reminedog/reminedog.log` に、`F3+C: clipboard hooks ready`、`world: <ワールドのフォルダ名>`、`options.txt: debug modifier ...`、`F3+C: requested (record)`、`F3+C: location captured (record)`、`waypoints: waypoint 1 recorded` の行がある。座標を取れないワールドでは `F3+C: refused (record)` が出る

うまくいかないときは `=log=debug` を付けて起動し、ログを送ってほしい。`F3+C:`、`world:`、`options.txt:`、`waypoints:` で始まる行が特に知りたい。

## ズームとキーの変更で確認すること

1.21.11 と 26.3 の両方で確かめてほしい。

- [ ] ゲーム中に Z を押している間、画面全体が拡大され、遠くのブロックの模様が拡大してもぼやけずに見える。上に「ズーム ×4.0」と出る
- [ ] Z を離すと元に戻り、視点が飛ばない。押すたびに何度でも使える
- [ ] 拡大している間に視点を動かしても、ふつうに回る
- [ ] Z を押したままインベントリ（E）を開くと、拡大が終わってインベントリがふつうに表示される
- [ ] 倍率を 2 と 8 に変えて、拡大のされ方と重さ（FPS）を見る
- [ ] メニューの「高精細にする」を外すと、以前と同じ引き伸ばす拡大になる
- [ ] メニューの「キー」でズームのボタンを押してから C を押すと、C でズームするようになる（Z はゲームに戻る）
- [ ] メニューを開くキーを Ctrl+M などに変えると、そのキーで開閉できる。「キーを元に戻す」で Ctrl+I・Z・J・K に戻る
- [ ] マウスのボタン 4 や 5（横のボタン）をズームに割り当てられる
- [ ] ゲームを再起動しても、変えたキーと倍率が残っている（ゲームフォルダの `reminedog/settings.json`）
- [ ] ウィンドウの大きさを変えたり F11 で全画面にしたりしてから拡大しても、正しく表示される

うまくいかないときは `=log=debug` を付けて起動してほしい。ログの `zoom:` で始まる行で、ゲームが縦長の解像度で描いたかどうかが分かる。
高精細が使えないと判断したときは、メニューのズームの欄に理由が出る。

## プロトタイプ 2 で確認したこと

起動直後の 10 秒間、画面の左上に「reminedog：Ctrl+I でメニューを開く」と出る。

- [ ] ゲーム中に Ctrl+I でメニューが開き、画面が少し暗くなる。マウスカーソル（白い矢印）が出る
- [ ] メニューを開いている間、マウスを動かしても視点が回らず、WASD でも歩かない
- [ ] メニューのスライダーやチェックボックスをマウスで操作できる
- [ ] チェックボックスや ▶ と、その横の文字の高さが揃っている
- [ ] ゲーム中（カーソルが消えている状態）に開いたメニューで、白い矢印がデスクトップのマウスカーソルと同じくらいの速さで動く（Windows の「ポインターの速度」と「ポインターの精度を高める」を変えると、次にメニューを開いたときから反映される）
- [ ] メニューの入力欄に日本語（IME）を入力できる（変換中の文字は欄に出ない。確定すると入る）。確かめたときの「入力のテスト」の欄はなくなったので、今はウェイポイントの「名前を変える」の欄で試す
- [ ] Ctrl+I か Esc でメニューが閉じ、視点が飛ばずにそのまま遊べる（Esc でポーズ画面が開かない）
- [ ] W を押したままメニューを開き、W を離してから閉じても、歩き続けない
- [ ] ゲーム中に Z を押している間、画面の中央が拡大され、上に「ズーム ×4.0」と出る。離すと戻る
- [ ] チャットの入力中に Z を押しても拡大されず、z が入力される
- [ ] ポーズ画面やインベントリを開いた状態で Ctrl+I を押してもメニューが開き、閉じると元の画面に戻る

うまく動かないときは `=log=debug` を付けて起動し、ログを送ってほしい。26.x では、ログの `SDL3 input:` で始まる行が特に知りたい（ゲームが入力をどの関数で読んでいるかが分かる）。

## プロトタイプ 1 で確認したこと

メニューの「状態」か、「メニューを閉じても状態を表示する」をオンにすると、次の情報が出る。

- [ ] 「フレーム」の数字が増え続け、「FPS」がゲームの FPS とおおむね同じ
- [ ] ワールドに入っても表示が崩れず、ゲームの描画もおかしくならない
- [ ] F11 で全画面にしても、ウィンドウに戻しても表示される
- [ ] ウィンドウの大きさを変えても表示される
- [ ] 最小化して戻しても落ちない
- [ ] ゲームを普通に終了できる（終了時に落ちない）
- [ ] DLL を外したときと比べて、FPS が大きく下がらない（ウィンドウの「処理時間」が 1 フレームあたりの重さ）

ゲームが起動しなくなったときは JVM 引数から `-agentpath:...` を外し、ランチャーのログ（`Could not find agent library` などの行）を送ってほしい。

うまくいかないときは、JVM 引数に `=log=debug` を付けて（`-agentpath:C:\reminedog\reminedog.dll=log=debug`）もう一度試す。

## 送ってほしいもの

- 確かめた Minecraft のバージョン、ランチャー（Prism／公式）、Mod ローダーの有無
- GPU（NVIDIA／AMD／Intel）
- 上のチェックの結果（スクリーンショットがあると助かる）
- ゲームフォルダの `reminedog/reminedog.log`
  - Prism Launcher：インスタンスのフォルダの中の `minecraft`（または `.minecraft`）
  - 公式ランチャー：起動構成の「ゲームディレクトリ」。空欄なら `%APPDATA%\.minecraft`
  - 分からないときは、オーバーレイの「ゲームフォルダ」の行を見る
- ウェイポイントで問題があったときは、ゲームフォルダの `reminedog/waypoints/` の中のファイルも

ログにはトークンなどの秘密の情報は書き出していない（コマンドラインは記録しない）。
ただし、ゲームフォルダや読み込んだ DLL のパスにはユーザー名が含まれることがある。

## ログの見方

| 行 | 意味 |
|---|---|
| `agent loaded` | JVM が DLL を読み込んだ |
| `DLL loaded: ...glfw.dll` | LWJGL が GLFW を読み込んだ場所（資料の未検証の前提 1） |
| `GLFW hooks installed` | `glfwSwapBuffers` をフックできた |
| `OpenGL hooks installed` | 高精細のズームのために `wglGetProcAddress` をフックできた |
| `F3+C: clipboard hooks ready` | 座標を取るためのフック（クリップボード、キー）が揃った。`F3+C: hooks missing; no waypoints` なら、ウェイポイントは使えない |
| `settings: ...` | 設定ファイルの場所と、メニュー・ズーム・記録・更新のキー |
| `options.txt: ...` | Minecraft の F3+C のキー（修飾キー、座標のコピー、クラッシュ）と、座標のコピーと同じキーに割り当てたほかの操作 |
| `world: ...` | 今のワールド（シングルプレイはフォルダ名、マルチプレイはサーバー）。`not in a world` はワールドの外、`unknown` は判定できていない |
| `F3+C: requested (...)` / `F3+C: location captured (...)` | 座標の取得を送った／座標が取れた（`manual` は自分で押した F3+C） |
| `F3+C: refused (...)` | ゲームが F3+C を受け付けなかった（デバッグ情報の制限） |
| `waypoints: waypoint N recorded` | 地点を記録して保存した（`renamed`・`removed` は名前の変更と削除） |
| `game GL: ...` | ゲームのコンテキスト（バージョン、GPU、core／compatibility） |
| `pixel format ...` | ウィンドウのピクセルフォーマット |
| `overlay GL: ...` | 自前のコンテキスト（資料の未検証の前提 5） |
| `overlay: first frame rendered` | 1 フレーム目を描けた |
| `[ERROR]` / `[WARN]` | 問題があった。内容を送ってほしい |

## Minecraft 26.x について

26.x は GLFW ではなく SDL3 でウィンドウを作り、OpenGL で描いている。reminedog は SDL3 の `SDL_GL_SwapWindow` をフックして、1.21 以前と同じようにオーバーレイを描く。
上の確認項目は 26.x でも同じ。ログには次の行が出る。

| 行 | 意味 |
|---|---|
| `SDL3 loaded` / `SDL3 hooks installed` | SDL3 を検出し、フックできた |
| `SDL_CreateWindow(... [OpenGL, hidden])` | 描画用の非表示の補助ウィンドウ。ここにはオーバーレイを出さない |
| `SDL_CreateWindow("Minecraft 26.x", ... [OpenGL])` | ゲームのウィンドウ |
| `renderer: OpenGL via SDL3` | OpenGL のコンテキストが作られた（Vulkan なら `Vulkan via SDL3` と出る。その場合はまだ描けない） |
| `window system: SDL 3.x.x` | オーバーレイが SDL3 のウィンドウに付いた |

| 1.20.1 | 17 | 3.3.1 | Core Profile。利用者が多い |
| 最新版 | 21 以降 | 3.3.3 以降 | 最新の GLFW |
